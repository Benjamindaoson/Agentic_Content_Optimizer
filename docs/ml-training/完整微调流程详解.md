## 🔧 具体怎么做微调？

### 微调方法：DPO (Direct Preference Optimization)

#### 什么是 DPO？

DPO 是一种**直接从偏好数据中学习**的微调方法，不需要显式的奖励模型。

**核心思想**:
- 给模型看两个输出：一个好的（chosen），一个差的（rejected）
- 让模型学会：增加好输出的概率，降低差输出的概率

#### DPO 损失函数

```python
L = -log(σ(β * (log π_θ(y_w|x) - log π_θ(y_l|x) - log π_ref(y_w|x) + log π_ref(y_l|x))))
```

**解释**:
- `y_w`: chosen（更好的输出）
- `y_l`: rejected（较差的输出）
- `π_θ`: 当前模型（正在训练）
- `π_ref`: 参考模型（冻结，不训练）
- `β`: 温度参数（控制学习强度）
- `σ`: sigmoid 函数

**直观理解**:
1. 计算当前模型对 chosen 和 rejected 的概率
2. 计算参考模型对 chosen 和 rejected 的概率
3. 让当前模型的概率差异大于参考模型的概率差异
4. 这样模型就学会了偏好

### 微调方法：LoRA (Low-Rank Adaptation)

#### 什么是 LoRA？

LoRA 是一种**参数高效微调**方法，只训练少量参数，大幅降低计算成本。

**核心思想**:
- 不直接修改原模型的权重
- 添加小的"适配器"矩阵
- 只训练适配器，冻结原模型

**数学表示**:
```
W' = W + ΔW
ΔW = BA

其中：
- W: 原始权重矩阵 (d × k)
- B: 低秩矩阵 (d × r)
- A: 低秩矩阵 (r × k)
- r << min(d, k)  (r 通常是 8 或 16)
```

**优势**:
- 只训练 1-2% 的参数
- 显存需求降低 3-4 倍
- 训练速度提升 2-3 倍
- 可以保存多个 LoRA 适配器，快速切换

### 完整训练代码

```python
# 1. 加载模型
model = AutoModelForCausalLM.from_pretrained("dots.llm1.inst")
ref_model = AutoModelForCausalLM.from_pretrained("dots.llm1.inst")

# 2. 应用 LoRA
lora_config = LoraConfig(
    r=8,  # 低秩维度
    lora_alpha=32,  # 缩放因子
    target_modules=["q_proj", "v_proj", "k_proj", "o_proj"],  # 应用到哪些层
    lora_dropout=0.1
)
model = get_peft_model(model, lora_config)

# 3. 准备数据
train_dataset = PreferenceDataset(preference_pairs, tokenizer)

# 4. 训练循环
for epoch in range(num_epochs):
    for batch in train_loader:
        # 计算当前模型的 log 概率
        chosen_logps = get_batch_logps(model, batch["chosen_input_ids"])
        rejected_logps = get_batch_logps(model, batch["rejected_input_ids"])

        # 计算参考模型的 log 概率
        ref_chosen_logps = get_batch_logps(ref_model, batch["chosen_input_ids"])
        ref_rejected_logps = get_batch_logps(ref_model, batch["rejected_input_ids"])

        # 计算 DPO 损失
        loss = compute_dpo_loss(
            chosen_logps, rejected_logps,
            ref_chosen_logps, ref_rejected_logps
        )

        # 反向传播
        loss.backward()
        optimizer.step()

# 5. 保存模型
model.save_pretrained("./models/dpo_finetuned")
```

## 🎯 微调的目的是什么？

### 目的 1：改进模型本身的生成能力

**问题**:
- 通用模型（Claude, GPT-4）虽然强大，但不一定适合特定场景
- 小红书内容有独特的风格和规律

**解决**:
- 使用小红书的真实爆款数据微调模型
- 让模型学会小红书的写作风格
- 提升内容的平台适配度

### 目的 2：基于真实反馈持续优化

**问题**:
- 初始模型可能不够好
- 用户偏好会变化
- 平台规则会更新

**解决**:
- 收集线上真实数据（点赞、评论、收藏）
- 生成偏好对（高互动 vs 低互动）
- 定期微调模型，持续改进

### 目的 3：降低成本

**问题**:
- 调用 Claude/GPT-4 API 成本高
- 每次生成都要付费

**解决**:
- 微调开源模型（Dots LLM）
- 本地部署，无 API 调用成本
- 性能接近商业模型，成本降低 90%

## 🔄 两层学习机制

### 快速层：GRPO 策略学习（每天）

**作用**: 学习哪些策略组合效果好

**方法**:
- 收集线上指标
- 计算每个策略（H/B/C 组合）的成功率
- 更新 Thompson Sampling 的概率分布

**效果**:
- 快速适应（24 小时）
- 低成本（只更新概率）
- 不改变模型本身

**比喻**: 像是调整"菜单"，决定推荐哪些菜

### 慢速层：DPO 模型微调（每周）

**作用**: 改进模型本身的生成能力

**方法**:
- 收集 7 天的真实数据
- 生成偏好对
- DPO + LoRA 微调模型
- 部署新模型

**效果**:
- 深度优化（7 天）
- 高成本（需要 GPU 训练）
- 改变模型本身

**比喻**: 像是提升"厨师技能"，做出更好的菜

metrics = await metrics_collector.collect_metrics(

### Step 2: 偏好对生成

**文件**: `backend/app/training/finetune_orchestrator.py`

**操作**:
```python
# 按质量分数排序
sorted_samples = sorted(
    high_quality_samples,
    key=lambda x: x.get("quality_score", 0),
    reverse=True
)

# 前 50% 作为 chosen，后 50% 作为 rejected
mid_point = len(sorted_samples) // 2
chosen_samples = sorted_samples[:mid_point]
rejected_samples = sorted_samples[mid_point:]

# 配对生成偏好对
for i in range(num_pairs):
    chosen = chosen_samples[i % len(chosen_samples)]
    rejected = rejected_samples[i % len(rejected_samples)]

    pair = PreferencePair(
        topic=chosen.get("topic"),
        platform=chosen.get("platform"),
        chosen_content=chosen.get("content"),  # 高分内容
        rejected_content=rejected.get("content"),  # 低分内容
        chosen_score=chosen.get("quality_score"),
        rejected_score=rejected.get("quality_score")
    )
```

**偏好对示例**:
```
Chosen (9.2分):
  标题：AI 写作工具推荐！效率提升 10 倍 ✨
  正文：最近发现了一个超好用的 AI 写作工具...
  CTA：关注我，分享更多效率工具 💡

Rejected (6.5分):
  标题：AI 写作工具
  正文：这是一个 AI 写作工具...
  CTA：点赞
```

### Step 3: DPO/LoRA 训练 ← **这里是微调！**

**文件**: `backend/app/training/dpo_trainer.py`

**操作**:
```python
# 1. 加载模型
dpo_trainer = DPOTrainer(config=DPOConfig(
    model_name="rednote-hilab/dots.llm1.inst",
    use_lora=True,
    lora_r=8,
    num_epochs=3,
    batch_size=4,
    learning_rate=5e-5,
    beta=0.1  # DPO 温度参数
))

dpo_trainer.load_model()

# 2. 训练
training_result = dpo_trainer.train(
    preference_pairs=train_pairs,
    validation_pairs=val_pairs
)

# 3. 保存模型
dpo_trainer.save_model("./models/dpo_finetuned")
```

**训练过程**:
1. 加载 Dots LLM 基础模型
2. 应用 LoRA 适配器（只训练 1-2% 参数）
3. 对每个偏好对：
   - 计算模型对 chosen 和 rejected 的概率
   - 计算 DPO 损失
   - 反向传播，更新 LoRA 参数
4. 保存微调后的模型

**训练时间**:
- 500 个偏好对：约 30-60 分钟（单 GPU）
- 1000 个偏好对：约 1-2 小时
- 5000 个偏好对：约 4-8 小时

### Step 4: 模型评估

**文件**: `backend/app/training/finetune_orchestrator.py`

**操作**:
```python
# 加载微调模型
dpo_trainer.load_finetuned_model(model_path)

# 生成评估样本
eval_topics = [
    "AI 写作工具推荐",
    "如何提升工作效率",
    "个人成长的 5 个技巧"
]

eval_results = []
for topic in eval_topics:
    # 使用微调模型生成内容
    generated_content = model.generate(topic)

    # 评估质量
    score = critic_agent.evaluate(generated_content)

    eval_results.append({
        "topic": topic,
        "score": score
    })

# 计算平均分
avg_score = sum(r["score"] for r in eval_results) / len(eval_results)

# 判断是否通过
passed = avg_score >= 8.0  # 阈值
```

**评估指标**:
- 内容质量分数（0-10）
- 平台适配度（0-100%）
- 生成速度（秒）
- 多样性分数（0-1）

# 监控新模型的表现
current_performance = await get_current_performance()

### 持续优化反馈循环

**文件**: `backend/app/rl/enhanced_online_learning_loop.py`

**操作**:
```python
# 每 7 天自动触发一次微调
while True:
    await asyncio.sleep(7 * 24 * 3600)  # 7 天

    # 检查触发条件
    if should_trigger_finetune():
        # 运行完整微调周期
        result = await finetune_orchestrator.run_full_cycle()

        if result["status"] == "success":
            logger.info("Finetune cycle completed successfully")
        else:
            logger.error(f"Finetune failed: {result['error']}")
```

**触发条件**:
1. 时间间隔：距离上次微调 >= 7 天
2. 样本数量：收集到 >= 1000 个新样本
3. 性能下降：当前性能 < 基线性能 * 0.9
